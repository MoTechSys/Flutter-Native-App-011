## 8. جلسة 1.3.0 — رموز التحقق عبر البريد الإلكتروني

### الطلب
1. عند إنشاء الحساب وعند استعادة كلمة المرور يُرسل رمز التحقق **إلى بريد المستخدم** فعلياً (حساب Gmail المطوّر كمُرسِل)، بمهلة **10 دقائق**، والرسالة بصيغة مناسبة والرمز **قابل للنسخ**.
2. حالة الاستخدام لنسيت كلمة المرور حرفياً: بريد → OTP للبريد → إدخال → **فحص المطابقة** → مطابق: كلمة مرور جديدة / مختلف: رسالة فشل.
3. خلل: بعد الخروج من التطبيق والعودة (لنسخ الرمز من البريد) لا تظهر لوحة المفاتيح في حقل الرمز/كلمة المرور.
4. رفع الإصدار كتحديث (نفس الحزمة، versionCode أعلى) ورفعه على المستودع مع التوثيق.

### القرارات
| القرار | السبب |
|---|---|
| حزمة `mailer` (SMTP مباشر من الجهاز) بدل خادم وسيط | لا يوجد Backend في المشروع (معيار الأستاذ: SQLite محلي)؛ SMTP من التطبيق أبسط طريقة لإرسال بريد فعلي بلا استضافة |
| بيانات SMTP عبر `--dart-define` من `android/smtp.env` المُتجاهَل | حتى لا تُرفع كلمة مرور التطبيق إلى GitHub العام؛ `build_release.sh` يقرأها تلقائياً و`smtp.env.example` يوضّح الشكل |
| `conditional import` (io/stub) | `mailer` يعتمد على `dart:io` ولا يعمل على الويب؛ نسخة الويب تعمل بوضع معاينة (الرمز يُعرض مع زر نسخ) لأخذ اللقطات والاختبار السريع |
| محرك OTP مستقل (`OtpSession`) بتجزئة SHA-256 | فصل المنطق عن الواجهة يسمح باختبارات وحدة دقيقة، ولا يُحتفظ بالرمز نصاً في الحالة |
| لوحة واحدة `OtpVerifyPanel` للشاشتين | نفس السلوك (عدّاد/محاولات/لصق/إعادة إرسال) بلا تكرار كود |
| إنشاء الحساب لا يكتب في SQLite قبل التحقق | حتى لا تبقى حسابات ببريد غير مؤكَّد؛ مغطّى باختبار |
| `KeyboardResumeFix` (unfocus → refocus → `TextInput.show`) عند `resumed` | المشكلة المعروفة في Flutter/أندرويد: بعد العودة من الخلفية يبقى الحقل مركَّزاً لكن IME لا يظهر؛ إعادة ربط التركيز صراحةً هي الحل المعتمد |
