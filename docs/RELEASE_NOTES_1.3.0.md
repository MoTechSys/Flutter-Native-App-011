# CarCare – ملاحظات الإصدار 1.3.0 (build 7)

> مستودع: `MoTechSys/Flutter-Native-App-011` · الحزمة: `com.carcare.maintenance`
> السابق: 1.2.0 (build 6) → **الحالي: 1.3.0 (build 7)**
> ملف التحكم عن بُعد `license.json` لم يتغيّر (الكود `CAR-7K2M`).

## ما الجديد باختصار
رموز التحقق (OTP) صارت **تُرسَل إلى بريد المستخدم فعلياً** عبر Gmail SMTP بدل عرضها داخل التطبيق، وأُضيف **تأكيد البريد قبل إنشاء الحساب**، وأُصلحت مشكلة **اختفاء لوحة المفاتيح بعد العودة إلى التطبيق**.

---

## 1. خدمة البريد الإلكتروني (جديد)
**الملفات:** `lib/services/mail/mail_service.dart`, `smtp_transport_io.dart`, `smtp_transport_stub.dart`

| العنصر | التفصيل |
|---|---|
| الحزمة | `mailer ^7.2.0` (SMTP خالص، يعمل على أندرويد) |
| الخادم | `smtp.gmail.com:465` (SSL) — كلمة مرور تطبيق (App Password) وليس كلمة مرور الحساب |
| الإعدادات | تُمرَّر **وقت البناء** عبر `--dart-define=SMTP_USER=… --dart-define=SMTP_PASS=…` ولا تُكتب في المستودع. مصدرها `android/smtp.env` (مُتجاهَل في `.gitignore`)، وسكربت `build_release.sh` يقرأه ويمرّره تلقائياً |
| الويب | لا يوجد SMTP في المتصفح → `conditional import` يختار `stub` وتعمل الشاشات في **وضع المعاينة** (الرمز يُعرض داخل التطبيق مع زر نسخ) — للتجربة وأخذ اللقطات فقط |
| المهلة | 25 ثانية للإرسال، ورسائل خطأ مفهومة (لا إنترنت / فشل التحقق / انتهت المهلة) |
| الاختبار | `MailService.transport` قابل للاستبدال + `debugCanSendOverride` للاختبارات |

### نموذج الرسالة
- **الموضوع:** `تأكيد البريد الإلكتروني — رمز التحقق 583914 | CarCare` (أو `استعادة كلمة المرور — …`).
- **HTML** بهوية التطبيق (كحلي `#0D1B2A` + برتقالي `#FF6B35`)، RTL، ترحيب باسم المستخدم، الرمز في صندوق كبير بخط monospace **قابل للنسخ بالضغط المطوّل**، تنويه بصلاحية 10 دقائق وعدم مشاركة الرمز، ونسخة نصية بديلة.
- تم التحقق حياً: أُرسل رمز من الساندبوكس عبر حزمة `mailer` نفسها ووصل إلى `alabbasi.elec@gmail.com` (`delivered=true`).

## 2. محرك OTP موحّد (جديد)
**الملف:** `lib/services/otp_service.dart`

| قبل (1.2.0) | بعد (1.3.0) |
|---|---|
| 4 أرقام | **6 أرقام** (`Random.secure`) |
| صالح 3 دقائق | **صالح 10 دقائق** |
| 3 محاولات | **5 محاولات** ثم يُلغى الرمز |
| رمز جديد فوراً | **إعادة إرسال بعد 60 ثانية** (تهدئة) |
| يُعرض للمستخدم فقط | **يُرسل بالبريد** (وضع المعاينة على الويب فقط) |
| الرمز محفوظ نصاً | يُحفظ **SHA-256(الرمز + البريد + الغرض)** — لا يُخزَّن نصاً صريحاً |
| كود في الشاشة | `OtpSession` + `OtpService` مستقلان عن الواجهة، مغطّيان باختبارات وحدة |

`OtpSession.verify(typed)` هي "الخطوة 4" من حالة الاستخدام: تُرجع `ok / wrong / expired / locked`.

## 3. لوحة إدخال الرمز `OtpVerifyPanel` (جديد)
**الملف:** `lib/widgets/otp_verify_panel.dart` — تُستخدم في الشاشتين (إنشاء حساب + استعادة كلمة المرور) لضمان نفس السلوك:
- بطاقة حالة: "تم إرسال رمز التحقق إلى بريدك" + البريد + إرشاد (افتح بريدك… تحقّق من الرسائل غير المرغوبة). في وضع المعاينة تعرض الرمز في 6 خانات + زر **نسخ الرمز**.
- حقل 6 أرقام: تركيز تلقائي، `autofillHints.oneTimeCode`، **تحقّق تلقائي عند اكتمال 6 أرقام**، زر **لصق من الحافظة** (يستخرج الأرقام فقط).
- عدّاد تنازلي حي للصلاحية، زر "إعادة الإرسال" مع عدّاد التهدئة، عرض "المحاولات المتبقية".
- رسائل الفشل صريحة: `فشلت العملية: الرمز غير صحيح (بقي N محاولة)` / `تم إلغاء الرمز بعد 5 محاولات` / `انتهت صلاحية الرمز`.

## 4. إنشاء الحساب بمرحلتين (تغيير سلوكي)
**الملف:** `lib/screens/auth/register_screen.dart`

```
[البيانات] الاسم/البريد/كلمة المرور/التأكيد ─► تحقق النموذج ─► البريد غير مسجّل؟ ─► إرسال الرمز
[تأكيد البريد] إدخال الرمز ─► مطابق؟ ─► INSERT users (هنا فقط) ─► رجوع لتسجيل الدخول
```
- **الحساب لا يُكتب في SQLite قبل نجاح التحقق** (مغطّى باختبار: `emailExists` = false قبل الرمز، true بعده).
- بريد مسجّل مسبقاً يُرفض **قبل** إرسال أي رمز.
- رأس مرحلتين (البيانات ← تأكيد البريد) بنفس أسلوب شاشة الاستعادة، زر رجوع لتعديل البيانات، `textInputAction` و`autofillHints` لكل حقل.

## 5. استعادة كلمة المرور — حالة الاستخدام المطلوبة حرفياً

## 6. إصلاح لوحة المفاتيح بعد العودة إلى التطبيق (إصلاح خلل)
**الملفات:** `lib/widgets/common.dart` (`KeyboardResumeFix`), `otp_verify_panel.dart`

**المشكلة:** المستخدم يغادر التطبيق (لفتح البريد ونسخ الرمز) ويعود، فيضغط على حقل الرمز/كلمة المرور ولا تظهر لوحة المفاتيح — الحقل يبدو مركَّزاً لكن قناة `TextInput` على أندرويد فقدت ارتباطها.

**الحل:** غلاف `KeyboardResumeFix` (يراقب `AppLifecycleState.resumed`) يلتف حول شاشات الدخول/التسجيل/الاستعادة: عند العودة يُلغي تركيز الحقل الحالي ثم يعيده بعد 150ms ويستدعي `TextInput.show` صراحةً؛ ولوحة OTP تعيد التركيز لحقل الرمز إن لم يكن هناك حقل مركَّز. لا يؤثر على الشاشات الأخرى.
